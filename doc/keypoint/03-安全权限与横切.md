# 03 · 安全、权限与横切能力

## 1. 认证：JWT + Refresh 轮换

| 项 | 实现要点 |
|----|----------|
| Access Token | JWT，默认约 **15 分钟** |
| Refresh Token | GUID，缓存键 `refresh:{token}`，默认约 **7 天** |
| 轮换 | 刷新时发新 Refresh，旧的失效（防盗用窗口缩小） |
| Claims | `NameIdentifier`、`Name`、`RoleId`、`TenantId` |
| SignalR | 支持 query `?access_token=`（浏览器 WebSocket 限制） |
| 密码 | BCrypt，workFactor=12 |

关键路径：`AuthService`、`TokenService`、`AuthController`。

**追问「为什么 Access 要短」**：泄露窗口小；业务无感靠 Refresh；Refresh 存服务端可吊销。

## 2. 授权：三层模型（必背）

```text
① 接口权限  [Permission("Xxx.Yyy")] → 动态 Policy；RoleId==1 超管放行
② 菜单/按钮  getMenu 动态路由 + 前端 v-permission（权限码与后端一致）
③ 数据范围  Features.DataScope：0全部 / 1本部门 / 2含下级 / 3仅本人
              → 业务主动调 IDataScopeService，**不是**全局 EF 过滤器
```

### 面试易错点

- 说「所有查询自动按部门过滤」→ **错**；DataScope 是显式调用。
- 说「关了菜单就没有 API」→ **错**；菜单与 API 权限码是两套控制面（再加上 Features UI 开关）。

## 3. Features 门控 vs Permission

| 机制 | 解决什么 | 失败表现 |
|------|----------|----------|
| `[RequiresFeature]` | 模块根本未交付/未采购 | **404** |
| `[Permission]` | 已交付但角色无权限 | **403** |
| 前端 features 过滤 | 菜单噪音 | 看不见入口，API 仍可能在 |

话术：**开关管产品形态，权限管人，缓存/租户管数据隔离**。

---

## 4. 多租户（当前边界）

- `BaseEntity.TenantId`；0 表示公共
- EF 全局 QueryFilter
- Claim → 请求管道写入 DbContext 过滤上下文
- **未实现**：每租户独立库、动态连接串、Schema 隔离

诚实说：「行级租户过滤已落地；强隔离多库是下一阶段。」

## 5. 横切中间件与安全件

| 能力 | 要点 |
|------|------|
| 异常处理 | 统一 `WebResponseContent` + 日志 |
| TraceId | 贯穿日志，便于联调 |
| 请求日志 | Serilog |
| IP 白名单 | `Security:IpWhitelist` 非空才拦 |
| 幂等 | `Features.Idempotency`，防重复提交 |
| 限流 | 登录/全局；关 Features 时额度极大相当于放行 |
| 验证码 | 登录防刷 |
| 字段审计 | `AuditSaveChangesInterceptor`；HotStore 落库实体可排除 |

## 6. 缓存（ICacheService）vs 后面的 HotStore

| | ICacheService | HotStore |
|--|---------------|----------|
| 场景 | 菜单、字典、配置等读多写少 | 路径边占用、车实时态等高频读写 |
| 模式 | 常 Cache-Aside + **延迟双删** | **热层即真相源**，运行期不回源 |
| 写后 | 删缓存，短暂可能穿透 DB | 改热层，Channel 脏数据批量落库 |
| 面试一句 | 「保证主数据最终一致、降低读库」 | 「保证调度节拍不被 DB/审计拖死」 |

把两者说混是大忌——见 [04](./04-HotStore与DeviceComm.md)。

## 7. 可观测性

| 端点 | 用途 |
|------|------|
| `/health` | K8s 探活：self、database、可选 redis/rabbitmq/minio |
| `/health-ui` | HealthChecks.UI 看板 |
| `/metrics` | Prometheus；Grafana 预置看板在 deploy |

MQ 路径示例：`RaiseAlarmCommand` → Consumer → 领域事件（Features.MessageQueue 开启时）。

## 8. 前端权限与 Features 协作

1. 登录拿 Token
2. 拉菜单（已按角色过滤）
3. 拉 `/api/config/features` 再滤掉未购买模块文件夹
4. 按钮级 `v-permission`
5. Axios 拦截：401 尝试 Refresh；失败跳登录

**亮点**：同一套后台可卖「轻量版 / 立库版 / 四向版」，配置驱动，无需拆仓库。
