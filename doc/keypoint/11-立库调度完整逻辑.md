## 1. 总体架构

```text
WMS BuildPallet / ApproveOutbound
  → Bus Leg
  → StackerWcsPack.AcceptLeg
       ├─ 入库 → PutAway(Accepted) → SUDR 巷→位 → DeviceTask[]
       └─ 出库 / StackerTransfer → Retrieval → Pri 门闩 → DepthGuard? → Path
  → StackerPathDispatcher（Dijkstra + ExeStack 合并）
  → SegmentFeedback 推进 RouteFlow
  → Completed → Bus → WMS
```

| 组件 | 职责 |
|------|------|
| `StackerAisleAllocator` / `LocationAllocator` | 选巷 / 选位 + Booking |
| `StackerInboundAllocator` | WMS 组盘入口 |
| `StackerDoubleDeepRules` | 防孤二深 / 入深条件 |
| `StackerDepthGuard` | 出库挡路 → Transfer |
| `StackerRouter` | Dijkstra（容量满边不可用） |
| `StackerPathDispatcher` | JudgeMap、拆腿、合并、占流 |
| `StackerDestinationService` | SUDR + 段反馈 + Pri 滚动 |
| `StackerWcsPack` | 接单契约 |
| `StackerOpsService` | 看板 / 强制完成 / 重发 |

## 2. 路径算法

### 2.1 JudgeMap

`Stk_DeviceCoder`：`LocationCode(Stk.*)` ↔ `PointCode`（路网/EP/输送）。无映射则原码。

### 2.2 Dijkstra

- 边：`Stk_Route`（MapCode、From/To、Weight、**Capacity**、**ExeStackCode**）  
- `Occupancy >= Capacity` → 边不可用  
- 代价：`Weight + Occupancy*0.01`  
- 输出：RouteId 序列  

### 2.3 拆腿与合并（任务下发关键）

```text
路径边序列
  → 连续相同 ExeStackCode 合并为 1× Stk_DeviceTask
  → 写 RouteFlow；仅 Seq=1 Dispatched
SegmentFeedback（匹配 Dispatched 段）
  → 释流 → 下一段 Dispatched
末段 → PutAway/Retrieval Completed
```

| 情况 | 决策 |
|------|------|
| 无图 / 同点 / 寻路失败 | **单段** DeviceTask |
| 同 ExeStack 多跳 | **合并**（减少设备碎片） |
| BlockingPoint | 作废在途段、释预约、重选位 |
| FeedbackCode≠OK / 非空且非 OK | **不**完成段、不推进（保持 Dispatched 可重试） |

## 3. 任务拆分与「合并」语义

| 层级 | 已实现 | 未实现 |
|------|--------|--------|
| Bus | Leg 1:1 → PutAway 或 Retrieval | 多业务单合腿 |
| 设备 | 路径按 ExeStack **段合并** | 双载 / 复合行程 |
| 出库组 | 同 `WcsGroupNo` + `WcsPri` 门闩顺序 | Special 紧急组 |

「任务合并」在本系统中 = **设备段合并**，不是 WMS 多单拼车。

## 4. 任务下发（Dispatch）

### 4.1 入库 SUDR

```text
AisleRequest/AP → SelectAisle → AisleAssigned → Dispatch(Ep)
LocationRequest/EP/Blocking → SelectLocation+Book → LocationAssigned → Dispatch(Bin)
Check≠OK → Reject+PutAway Failed
  （若源点是启用中的四向 RP → 静默，不误伤）
```

SelectAisle：过滤策略/高重/盘点锁/`MinEmptySlots`；排序 `AllocationWeight↓ → LastAssignedAt↑ → AisleCode`。

### 4.2 出库

```text
AcceptRetrieval
  → 同组更小 Pri 未终态 → Suspended
  → DepthGuard（见 §5）
  → PathDispatcher From→To
  → Dispatched；完成滚下一 Pri
```

## 5. 双深逻辑

### 5.1 分配期（防孤二深）

- 深位仅当同 `BinGroupCode` **更浅已占用或已预约**  
- 排除 `InLockBin`  
- 排序：Depth → Layer → Column → Row → Code（浅优先）  
- Booking：目标 `IsBooked`；同组其它空位一并预约  

SRM Demo：每列每层天然一对 depth1/2 → 直接覆盖「先深后浅非法」「组预约防插队」用例。

### 5.2 出库期（DepthGuard）

```text
取深位被浅位挡
  → 深 Retrieval：WcsPri+1 + Suspended
  → 建 Bus RefType=StackerTransfer：浅 → 同巷空位（原 Pri）
  → Transfer 完成 → 再派深位
```

Transfer 目标：同巷首个空闲（**未**复用完整双深安全选位——已知偏弱）。

## 6. 高低货位

| 层级 | 现状 |
|------|------|
| 巷道策略 | SUDR `Height/Weight` 对照 `MaxHeight/MaxWeight` **过滤巷** |
| 货位 | `WmsLocation` 仅 Layer/Column/Row/Depth；**无**货位高度档字段 |
| Demo 数据 | BeamRack `cellHeight`、CoordPoint `elevation` 在 fixture，供后续扩展与用例标注 |

**结论**：当前「高低」= **策略限高过滤巷道**，不是 LES 式货位高低匹配。用例分「已实现限高」与「扩展缺口」两类。
