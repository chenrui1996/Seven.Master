## 1. 总体架构

```text
WMS / Ops inbound
  → Bus_TransportLeg (一次搬运意图 = 1 Leg)
  → FourWayWcsPack.AcceptLeg
       ├─ 同层入库 → PutAway + Shuttle(Accepted) → SUDR 层→巷→位
       ├─ 出库/FourWayTransfer → Retrieval + 停车账本 + Pri 门闩
       └─ 跨层 → HoistTask 包内三阶段（总线仍 1 Leg）
  → FourWayPathDispatcher（层内 Dijkstra + TrafficGuard）
  → SegmentFeedback / Scheduler(3s) 推进、重试、唤醒
  → Bus Completed → WMS 库存
```

| 组件 | 职责 |
|------|------|
| `FourWayInboundAllocator` | 层→巷→位；权重轮转；MinEmpty / MaxShuttle |
| `FourWayDestinationService` | SUDR + 段反馈；Hoist 优先消费 |
| `FourWayRouter` | 有向加权 Dijkstra |
| `FourWayPathDispatcher` | 选图、写 Path、首跳占边、Advance/Retry |
| `FourWayTrafficGuard` | 边级互斥（HotStore `fw:flow:`） |
| `FourWayHoistOrchestrator` | 跨层三阶段 + 同口 Exec 排队 |
| `FourWayWcsPack` | 接单 / Retrieval / 停车 / CanHandle |
| `FourWaySchedulerHostedService` | Routing 重试 / 停车 Promote / Hoist 补扫 |
| `FourWayOpsService` | 监控、强制完成、指定点、充电旁路 |

## 2. 路径算法（层内）

### 2.1 选图

`ResolveMapVersionId`：

1. 显式 MapVersionId  
2. **LayerCode** 匹配（Active 优先）  
3. 全局 Active  
4. 首条 Map  

新加坡：两层各一张 Active 图（fixture 中 `FW-SingaporeShuttleProject-Fw.L0x`）。

### 2.2 Dijkstra

- 输入：`Fw_Route` 有向边，`Weight = max(w,0)`  
- 节点码大小写不敏感  
- **当前未用** `Capacity` / `RouteGroup`（与立库不同）  
- 输出：节点序列 → `Fw_ShuttleTaskPath`（Seq、NodeCode、EdgeId=`Route.Id`）

### 2.3 下发与推进

```text
写 Path
  → TrafficGuard.TryGrant(首跳 EdgeId, owner=ShuttleTaskId)
       OK  → Shuttle=Running + DispatchDestination(下一节点)
       NG  → 保持 Routing（不下发；Scheduler 周期 Retry）
SegmentFeedback OK
  → Release 当前边 → Grant 下一跳 → Dispatch
末跳完成 → Shuttle/PutAway Completed → Bus
```

### 2.4 退化与冲突决策

| 情况 | 决策 |
|------|------|
| 无 Map / 无边 / from==to / 寻路空 | **单段** From→To（无 EdgeId） |
| 占边失败 | **不 Failed**；Routing + 周期重试 |
| Cancel/Fail | 释尽 path EdgeId ∪ owner 索引 |
| 对向同边 | 同一 `edgeId` 互斥（V1 把对向也视为同资源） |

**不是**：节点占用、死锁检测、动态绕路、时间窗、容量>1。

## 3. 任务拆分

| 层 | 规则 |
|----|------|
| Bus | **永不**因跨层拆多 Leg |
| AcceptLeg | 不同层 → Hoist；出库 RefType → Retrieval；否则 PutAway |
| 层内 | 1×`Fw_ShuttleTask` + N×Path 行（一步一目的地） |
| 跨层 | `HoistTask.Stage`：`ToSrcAp` → `HoistLift` → `FromDesEp` → `Done` |

---

## 4. 交通管制（TrafficGuard）

- 资源粒度：**边** `edgeId`  
- 存储：HotStore `fw:flow:{edgeId}`（生产禁用 Demo 全局 `wcs:`）  
- 同 owner 幂等 Grant  
- 一步一授予：与段反馈耦合，形成「移动走廊」的最小交通模型  

**冲突路径决策（V1）**：后到者拿不到边 → 停在 Routing 等待；**不**自动重规划。现场恢复靠 Scheduler + 运维强制完成/重发。

---

## 5. 停车点选择（出库）

```text
TryDispatchRetrieval
  → 同组更小 WcsPri 未终态？ → Suspended
  → 选车位：Status=Free ORDER BY Id 取首（全局，非就近）
  → UPDATE … WHERE Status=Free → Reserved（原子，最多重试 8）
  → PathDispatcher；仅 Running 后 → Occupied + Retrieval Dispatched
  → 段完成 → Free；滚下一 Pri
  → 无 Free → Suspended；Scheduler 发现 Free 再唤醒
```

| 状态 | 含义 |
|------|------|
| Free | 可抢 |
| Reserved | 已分给任务、车未实占（防双抢） |
| Occupied | 执行中实占 |

新加坡 fixture 为每层预置 1 个 `Fw.PARK-*`，多车并发用例应扩容多条 Free 账本。

**缺口**：不按层/巷就近；不绑物理车号；无「空闲回库」主动调度。

## 6. 提升机资源占用

### 6.1 选型与口

- 设备 Available +100 / 不可用 −1000 / 无台账 +50；口无 Dispatched +10；同分比 HoistNo  
- 出库 Ref 优先 Outbound Ap/Ep，否则 Inbound，再交叉回退  

新加坡：单台 `PalletLift`，两层 docking → 最适合测「同口排队 + 三阶段」。

### 6.2 三阶段

```text
① ToSrcAp：货位 → 源层 Hoist AP（层内 Path+交通）
② HoistLift：同口仅 1×Dispatched；队首按 Pri↑ 再 CreateDate；否则 Suspended
③ FromDesEp：目标层 EP → 目标货位
Feedback≠OK：到 AP/目标不推进；抬升可 Failed 并唤醒队列
```

### 6.3 占用粒度

`HoistNo + SrcAddress`；抬升成功写 `Fw_HoistDevice.CurrentLayer/Location`；Scheduler 补扫 Queued。

## 7. 入库分配（层→巷→位）

| 阶段 | 规则 |
|------|------|
| 层 | Preferred 或 `Fw_LayerPolicy`：可用、高重限重、Zone；`AllocationWeight↓` + `LastAssignedAt↑` |
| 巷 | Preferred 或 `Fw_AislePolicy`：`MinEmptySlots`（**本层**）、`MaxShuttleCount`（该层巷 Parking Reserved+Occupied） |
| 位 | 同仓同巷空闲未锁未订；`OrderBy Code`；`IsBooked=true` |

SUDR：`Layer/AisleRequest` → 下发巷 Ep；`LocationRequest` → Book 后下发 Bin。  
Hoist/Shuttle 口类型的 RequestPoint：**外形 NG 时勿误 Reject**（靠段反馈）。

## 8. 状态机速查

```text
PutAway: Accepted → LayerAssigned → AisleAssigned → LocationAssigned → Completed|Failed|Cancelled
Shuttle: Accepted → Routing → Running → Completed|Failed|Cancelled
Retrieval: Accepted → Suspended? → Dispatched → Completed|…
Parking: Free → Reserved → Occupied → Free
HoistTask: Accepted → Running；Stage ToSrcAp → HoistLift → FromDesEp → Done
HoistExec: Queued → Suspended? → Dispatched → Completed|Failed
```

控制：`IControlModeService` 急停/手动可拒接单。

## 9. 与「完整 RCS」差距（完整对照）

### 9.1 已落地（可证）

| 能力 | 实现锚点 | 主测 |
|------|----------|------|
| 层→巷→位 + Booking | `FourWayInboundAllocator` | `FourWayAllocatorTests` / `InboundToFourWayE2ETests` |
| Dijkstra + 边互斥 + Routing 重试 | `FourWayRouter` / `FourWayPathDispatcher` / `FourWayTrafficGuard` | `FourWayPathDispatcherTests` / `FourWaySingaporeMapTests` |
| 停车 Free→Reserved→Occupied | `FourWayWcsPack.TryReserveParking*` | `FourWayParkingTests` / `OutboundToFourWayE2ETests` |
| 跨层单 Leg 三阶段 + 同口排队 | `FourWayHoistOrchestrator` | `FourWayHoistE2ETests` |
| Scheduler 可恢复扫描 | `FourWaySchedulerHostedService` | 间接（Hoist ScanAndWake / Parking Promote） |
| 运维 board / 指定点 / 充电旁路 | `FourWayOpsService` | 活库 ApiHttp（DotNet 仍薄） |

### 9.2 差距矩阵（产品边界，非 stub）

| ID | 差距项 | 现状 | 影响 | 测试态 |
|----|--------|------|------|--------|
| G-FW-01 | 节点占用 / 死锁解脱 | 仅边级 `fw:flow:{edgeId}` | 交叉口对向/环死锁靠人工 | 无专门用例；冲突仅边互斥 |
| G-FW-02 | 占边失败后重规划 | 保持 Routing，周期 Retry **同路径** | 堵边时不会绕路 | TC-FW-SG-002 只断言不 Failed |
| G-FW-03 | `FwRoute.Capacity` / `RouteGroup` | 实体有字段，Router **不读** | 不能表达「边容量>1」 | 立库有容量测；四向无 |
| G-FW-04 | 就近停车 / 按层巷过滤 | `OrderBy Id` 取首个 Free | 跨层可抢「远处」车位 | TC-FW-SG-020 只验三态 |
| G-FW-05 | 物理车池派车 | 无 Shuttle 台账实时位 | 监控「本层车」弱代理 | Ops 监控 Browser |
| G-FW-06 | 空闲回库主动调度 | 无 | 车停任务终点 | Gate |
| G-FW-07 | 完整充电 / SOC / 避让矩阵 | Ops `ChargeAsync` 仅建运输单 | 非真充电态机 | TC 运维旁路 |
| G-FW-08 | ForceComplete 释资源 | **已修**：释边 + 停车回 Free | — | TC-FW-SG-042 → P0 |
| G-FW-09 | 多实例 HotStore 边索引 | 进程内 `_ownerEdges` + HotStore | 多实例释边弱 | 单测 InMemory |
| G-FW-10 | Phase H 真机 Port / F6 Promote | Trigger 仿真 | 现场换 Port | Manual |

### 9.3 决策速查（面试）

| 问题 | V1 决策 |
|------|---------|
| 两车争同边？ | 先到 Running；后到 Routing；不 Failed、不绕路 |
| 跨层怎么拆？ | Bus **仍 1 Leg**；包内 Hoist 三阶段 |
| 无车位？ | Retrieval Suspended；有 Free 再 Promote |
| 同组多出库？ | 更小 `WcsPri` 未终态则挂起 |
