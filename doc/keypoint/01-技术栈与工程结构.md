## 2. 解决方案分层（必背）

```
Seven.WebApi          Controllers / Hubs / Program / Swagger
        ↓
Seven.Application     I*Service、DTO、WCS/WMS 契约（无 EF）
        ↓
Seven.Domain          实体、枚举、BaseEntity、统一响应

Seven.Infrastructure  EF、JWT、Cache、HotStore、DeviceComm、Wcs、Wms、中间件
Seven.Business        工作流等可独立演进业务
Seven.Builder         代码生成
Seven.Tests           单元 + WebApplicationFactory 集成
```

**依赖方向**：`WebApi → Application → Domain ← Infrastructure / Business / Builder`

### 面试要点

- **为何 Application 不引用 EF**：契约与实现分离，测试可 Mock，换存储不影响接口形状。
- **为何没有独立 Repository/UoW**：务实取舍——Service 内直接 `SevenDbContext`，事务边界在 Service 方法；避免过度抽象。架构愿景里的 Specification 等**未落地**，别吹成已有。
- **统一响应**：`WebResponseContent { status, message, data, code }`，JSON **camelCase** 对齐前端。

## 5. 测试怎么体现工程素质

仓库用 **过滤器命名空间** 区分域，面试可提「按业务切片跑回归」：

```powershell
# 立库
dotnet test --filter "FullyQualifiedName~Stacker|…StackerDoubleDeep|…StackerPath"

# 四向
dotnet test --filter "FullyQualifiedName~FourWay|…InboundToFourWay|…"

# 平台 + WMS 宽口径
dotnet test --filter "FullyQualifiedName~Wms|…Wcs|…Orchestration|…"
```

**亮点话术**：关键路径（组盘→总线→包→段反馈→落账）有端到端测试，不只是单测 Mock。

## 6. 与「传统仓储软件」对比一句话

多数 WMS/WCS 分两套系统、两套库位；Seven 选择 **同一进程共享 `Wms_Location`/`Wms_Stock`**，用 Pack 前缀与总线隔离设备差异——这是产品级架构决策，不是简单 CRUD 堆功能。
