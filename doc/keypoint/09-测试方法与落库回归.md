# 09 — 测试方法与落库回归（主流方式）

面试/复盘时：讲清「怎么证系统对」，比背用例 ID 更重要。本文归纳 Seven.Master **当前主流测试手段**、分层职责、以及 **落库保留** 回归怎么做。

配套：[`testplan/`](../../testplan/README.md)、[`doc/24-运维Ops与联锁`](../24-运维Ops与联锁.md)。

---

## 1. 一句话分层（背）

> **DotNet InMemory** 证领域正确；**ApiHttp 活库** 证路由/权限/契约与真实落库；**Playwright** 证菜单 IA 与关键页可开；**落库保留前缀 `RETAIN*`** 给人眼验收；仿真 Trigger 证设备闭环。

---

## 2. 四条主流流水线

| 方式 | 工程/脚本 | 数据落哪 | 何时用 |
|------|-----------|----------|--------|
| **A. xUnit 服务 E2E** | `Seven.Net8/Seven.Tests` | **进程内 InMemory**，测完即灭 | P0 账本/分配/拆腿/Hoist；CI |
| **B. ApiHttp 活库只读+契约** | `testplan/scripts/run-api-cases.ps1` | 真实库，**少写** | 菜单 IA、Ops GET、登录/Captcha、401 |
| **C. ApiHttp 落库保留** | `run-retain-cases.ps1` / **`run-retain-locations.ps1`** | 真实库，**故意保留** `RETAIN*` / 地图 `Stk.*`·`Fw.*` | 联调演示、人眼验收、**库位主数据** |
| **D. Playwright 浏览器** | `testplan/e2e` | 不依赖写库；可断言 UI 可见 | 登录验证码、运维页、无「执行运维」 |

另：**Manual / Simulator** 用于真机或黄金路径录制，不替代 A–D。

### 2.1 A — DotNet（最多、最快）

```powershell
cd Seven.Net8
# 独立 -o，避免锁住正在跑的 WebApi bin
dotnet test Seven.Tests\Seven.Tests.csproj -o ..\testplan\reports\testbin `
  --results-directory ..\testplan\reports\dotnet
```

典型类：`InboundToStackerE2ETests`、`FourWayHoistE2ETests`、`WmsOrderServiceTests`、`OrchestrationBusTests`。  
Trait/钩子约定见 `testplan/00-conventions.md`（`Hook` / `CaseId`）。

**面试点**：为何 InMemory？——隔离快、可重复；不替代活库契约测试。

### 2.2 B — 活库 ApiHttp（读为主）

- 登录：`GET /api/Captcha/create` → `POST /api/Auth/login`（`verificationCode`+`uuid`）
- 断言 Features、`getMenu` 无「执行运维」、Ops `board/meta/control-mode`
- **易错契约**（实测踩过）：
  - `control-mode.mode` 必须是 **数值枚举**（0=Auto,1=Manual）
  - `force-complete` 字段名是 **`targetType`**，不是 `kind`

### 2.3 C — 落库并保留（本次补强）

计划：[`testplan/retain-data-e2e.md`](../../testplan/retain-data-e2e.md)

```powershell
powershell -ExecutionPolicy Bypass -File testplan\scripts\run-retain-cases.ps1
```

| 前缀 | 含义 |
|------|------|
| `RETAIN_WH` | 测试仓 |
| `Stk.RETAIN.*` | 库位（须 Pack 前缀或 `packId`） |
| `RETAIN-IN-/OUT-/CC-` | 入/出/盘点单号 |
| `RETAIN-TP-*` | 容器 |
| `RETAIN.RP-01` | 立库申请点 |

**策略**：默认 **不清理**；UI 按前缀搜索即可看到单据与库存。

**实测注意**：

1. 库位编码无 `Stk.`/`Fw.` 且无 `packId` → 业务拒批。  
2. 活库若 WebApi 未开 `ReferenceHandler.IgnoreCycles`，`add` 可能 **业务已写入但 HTTP 500（JSON 环）**；脚本用「按单号回查 id」兜底。代码侧已补 `IgnoreCycles` + `JsonIgnore` 导航，**需重启 WebApi** 后 500 消失。

### 2.4 D — Playwright

```powershell
cd testplan\e2e
npx playwright test
# 落库可见性：npx playwright test specs/retain-ui.spec.ts
```

登录可读页面 `.captcha-code`（与 Captcha API 明文 code 一致，便于自动化）。

Chrome MCP 附着用户浏览器若失败，用独立 Chromium 即可，不必阻塞回归。

## 3. 用例 ↔ 自动化映射（讲故事用）

```text
设计/用例 (testplan/cases)
        │
        ├─ ExistingTest ──► Seven.Tests Fact（A）
        ├─ ApiHttp Hook ──► run-api-cases / run-retain-cases（B/C）
        ├─ Browser UiTestId ──► Playwright（D）
        └─ Manual ──► 现场/仿真
```

报告目录：

- 总报告 / 只读冒烟：`testplan/TEST-REPORT-*.md`
- 落库保留：`testplan/reports/retain/`
- 未通过：`testplan/failed/`

---

## 4. 面试可答「你们怎么测 WMS/WCS」

30 秒版：

> 核心闭环用 xUnit + InMemory 包级 E2E；上线前用活库脚本打登录、菜单、Ops 契约；联调要给人看数时用 `RETAIN*` 落库保留脚本；UI 用 Playwright 冒烟。设备用 TriggerPort 仿真，真机换同一接口。

追问「为何上次系统里没数据 / 没库位」：

> 那次若只跑了 A（InMemory）或 B（只读），活库几乎无写；`run-retain-cases` 也只写 2 个 `Stk.RETAIN.*`。**地图级库位**要用 C-LOC：`run-retain-locations.ps1`（SRM Demo / 新加坡 fixture → MySQL KEEP）。

---

## 5. 与平台其它测试的关系

| 能力 | 测法 |
|------|------|
| Features 裁剪 | `FeatureOptionsWcsTests` + 活库 `/api/config/features` |
| 权限/菜单 | `getMenu` / `getMenuList` + Playwright 侧栏 |
| HotStore / DeviceComm | 专项单测（见 doc 15/16）；默认 Features 关则不测真链路 |
| 仿真器 | `SimGatewayTests`、doc/21 |
