# 后端开发指南

本文说明 Seven.Net8 的分层、启动管道、认证授权、EF Core、缓存，以及如何新增业务模块。对照仓库根目录 [系统架构设计.md](../../系统架构设计.md)：本文只写**已落地**能力；愿景中的 OAuth、Repository/UoW、配置中心等标为未实现。

环境与启动见 [01-快速开始](./01-快速开始.md)。功能裁剪见 [14-功能开关](./14-功能开关.md)。

---

## 1. 分层与项目职责

### 1.1 依赖方向

```
Seven.WebApi          → Controllers、Hubs、Program、Swagger、健康检查
Seven.Application     → 服务接口、DTO、消息契约（无基础设施依赖）
Seven.Domain          → 实体、枚举、BaseEntity、WebResponseContent
Seven.Infrastructure  → EF、缓存、JWT、安全、MQ、Quartz、存储、邮件、中间件
Seven.Business        → 业务域服务（如工作流引擎）
Seven.Builder         → 代码生成器实现
Seven.Tests           → 单元 / 集成测试
```

依赖方向：`WebApi → Application → Domain ← Infrastructure / Business / Builder`

**原理**：Application 只定义契约，Infrastructure 实现技术细节。业务代码依赖接口（如 `ISysUserService`、`ICacheService`），便于测试与替换 Redis/本地存储。Domain 不引用 EF，实体保持纯 POCO。

未采用独立 Repository / UnitOfWork：Service 直接注入 `SevenDbContext`，事务边界放在 Service 方法内。架构文档第七章中的 Specification、CompiledQuery 等未引入。

### 1.2 解决方案项目职责

| 项目 | 职责 |
|------|------|
| **Seven.Domain** | 纯领域模型：`Entities/*`、`Enums`、`Common`（`BaseEntity`、`ISoftDelete`、统一响应） |
| **Seven.Application** | 应用层契约：`I*Service`、请求/响应模型、MQ 事件定义；不引用 EF |
| **Seven.Infrastructure** | 技术实现与横切：DbContext、种子、缓存、认证授权、限流/防重、文件、邮件、MassTransit、Quartz、Options |
| **Seven.Business** | 可独立演进的业务服务（当前含 `WorkFlowService`），由 `AddSevenBusiness()` 注册 |
| **Seven.Builder** | 读表结构、生成 Entity/Service/Controller/Vue 模板代码 |
| **Seven.WebApi** | HTTP 入口：`Program.cs`、Controllers、SignalR Hubs、生成模板 `Template/`、`Generated/` |
| **Seven.Tests** | FluentAssertions + WebApplicationFactory 等 |

### 1.3 Infrastructure 文件夹

| 目录 | 说明 |
|------|------|
| `Configuration/` | Options（Database/Cache/Jwt/Features/…） |
| `Persistence/` | `SevenDbContext`、Configurations、Migrations、DbSeeder、审计拦截器 |
| `Services/` | 系统模块服务（用户/角色/菜单/字典/日志/告警/设备…）、CrudHelper |
| `Security/` | JWT、验证码、`[Permission]`、`[RequiresFeature]`、DataScope |
| `Middleware/` | 异常、TraceId、请求日志、IP 白名单、防重 |
| `Caching/` | Memory/Redis + 延迟双删（主数据） |
| `HotStore/` | 运营热数据：预热、占用锁、异步落库（需 `Features.HotStore`） |
| `Storage/` | 本地 / MinIO 文件存储 |
| `Messaging/` | MassTransit、Consumer、Outbox |
| `Quartz/` | 调度宿主与任务服务 |
| `Mail/` | MailKit 发信 |

### 1.4 WebApi 文件夹

| 目录/文件 | 说明 |
|-----------|------|
| `Controllers/` | 手写系统 API；`Generated/` 为代码生成产物 |
| `Hubs/` | MessageHub / AlarmHub 与推送服务 |
| `Template/` | Builder 生成用的 HTML/CS 模板 |
| `Program.cs` | 管道、Swagger 分组、Features 门控 MapHub |
| `appsettings*.json` | 环境配置；**Features** 见 [14-功能开关](./14-功能开关.md) |

## 2. 启动与管道（Program.cs）

### 2.1 注册阶段（原理）

1. **Serilog**：控制台 + `logs/seven-.log` 按日滚动。
2. **Features**：读 `Features` 配置节，决定后续中间件、Hub、Quartz/MQ 等是否启用。
3. **DI**：`AddSevenInfrastructure` → `AddSevenBusiness` → Builder / SignalR 推送实现。
4. **MVC**：JSON **camelCase**，与前端约定一致。
5. **Swagger**：四个文档分组 `system` / `workflow` / `builder` / `ops`（按 Controller 上 `[ApiExplorerSettings(GroupName)]`）。
6. **SignalR**：服务**始终**注册（`IHubContext` 推送依赖）；是否 `MapHub` 由 `Features.SignalR` / `Features.Alarm` 控制。
7. **健康检查**：`/health`（self、infrastructure、redis、rabbitmq、minio）。
8. **CORS**：开发允许 `localhost` / `127.0.0.1` 任意端口；生产读 `Cors:Origins`。

核心扩展入口：`Seven.Infrastructure/DependencyInjection.cs` 的 `AddSevenInfrastructure`。

### 2.2 请求管道顺序

顺序即责任链：越靠前越先看到请求、越后看到响应。

```
ExceptionHandlingMiddleware     统一异常 → WebResponseContent
TraceIdMiddleware               链路 TraceId（日志关联）
RequestLoggingMiddleware        请求日志
IpWhitelistMiddleware           Security:IpWhitelist 非空才拦截
IdempotencyMiddleware           Features.Idempotency 时启用
ResponseCompression
RateLimiter                     Features.RateLimit 为 false 时额度极大
Swagger（仅 Development）
StaticFiles + /upload
Cors
Authentication / Authorization  JWT Bearer
租户上下文中间件                 解析 TenantId Claim → DbContext 过滤器
MapControllers
MapHub（按 Features）
MapHealthChecks /health
启动时 DbSeeder（非 Testing）
```

**用法提示**：

- 新横切能力优先做成中间件并插在 Auth 之前或之后（视是否需要身份）。
- 业务校验放 Controller / Service，不要塞进异常中间件。
- JWT 由框架 `JwtBearer` 完成，无自定义 JWT 中间件。

### 2.3 功能开关

复杂能力默认可关，见 **[14-功能开关](./14-功能开关.md)**。  
Controller 使用 `[RequiresFeature("WorkFlow")]` 等；关闭后返回 404。

## 3. 认证：JWT + Refresh Token

### 3.1 模型（原理）

```
登录成功
  ├─ Access Token（JWT，短时，默认 15 分钟）→ Authorization: Bearer …
  └─ Refresh Token（GUID，长时，默认 7 天）→ 存 ICacheService：refresh:{token}
```

| 环节 | API | 行为 |
|------|-----|------|
| 登录 | `POST /api/Auth/login` | 校验用户/密码（可选验证码）→ 发双 Token → 写登录日志 |
| 刷新 | `POST /api/Auth/refresh` | 读缓存 → **轮换**（删旧 refresh，发新双 Token） |
| 登出 | `POST /api/Auth/logout` | 删除 refresh 缓存（吊销） |
| 权限 | `GET /api/Auth/permissions` | 按当前角色重新拼权限码列表 |

关键文件：

| 角色 | 路径 |
|------|------|
| Controller | `Seven.WebApi/Controllers/SevenControllers.cs` → `AuthController` |
| 业务 | `Seven.Infrastructure/Services/AuthService.cs` |
| Token | `Seven.Infrastructure/Security/TokenService.cs` |
| 密码 | `Seven.Infrastructure/Security/BcryptPasswordHasher.cs` |

JWT Claims：`NameIdentifier`（用户 Id）、`Name`、`RoleId`、`TenantId`。  
SignalR 连接支持 query：`?access_token=`（与 HTTP Header 同源 Token）。

**未实现**（相对架构文档第四章）：Cookie 会话、OAuth2 / OpenID Connect、ASP.NET Identity。

### 3.2 密码（BCrypt）

- 哈希：`IPasswordHasher` → `BCrypt.HashPassword(pwd, workFactor: 12)`
- 验证：`BCrypt.Verify`
- 禁止明文或可逆对称加密存库
- 旧数据迁移可设 `MustResetPassword = true`，首次登录强制改密

### 3.3 登录时权限如何生成

1. 查 `Sys_RoleAuth`（当前 `Role_Id`）+ 关联 `Sys_Menu`
2. 对每个授权菜单：用菜单 `TableName` + `AuthValue` 中勾选的动作，拼成 `{TableName}.{Action}`（如 `Device.Add`）
3. **仅使用角色已勾选的 AuthValue**，不会回退成菜单上定义的全部 Auth

超级管理员约定：`RoleId == 1` 在接口授权 Handler 中直接放行（见下一节）。

### 3.4 配置项（`Jwt`）

```json
{
  "Jwt": {
    "Secret": "至少32字符的密钥",
    "Issuer": "Seven",
    "Audience": "Seven",
    "AccessTokenMinutes": 15,
    "RefreshTokenDays": 7
  }
}
```

Refresh 存在缓存中：切换 `Cache:Provider` 为 Redis 后，多实例共享吊销状态；Memory 仅单机有效。

## 4. 授权三层

接口权限、菜单/按钮权限、数据权限是三套机制，不要混为一谈。细节配置见 [04-权限与菜单](./04-权限与菜单.md)、[13-安全与数据权限](./13-安全与数据权限.md)。

### 4.1 接口权限（`[Permission]`）

```csharp
[Authorize]
[HttpPost("add")]
[Permission("Device.Add")]
public async Task<WebResponseContent> Add([FromBody] Device dto) { ... }
```

**原理**：

1. `[Permission("Device.Add")]` 映射为 Policy 名 `perm:Device.Add`
2. `PermissionPolicyProvider` 动态提供 Policy
3. `PermissionAuthorizationHandler`：未登录失败；`RoleId == 1` 通过；否则按库中角色权限判断

实现：`Seven.Infrastructure/Security/PermissionAuthorization.cs`。

### 4.2 菜单 / 按钮权限

- 菜单树：角色可见菜单 → `GET /api/Sys_Menu/getMenu` → 前端动态路由
- 按钮：前端 `v-permission="'Device.Add'"` 或 `hasPermission`，权限码与接口一致

配置步骤与 Import/Export 勾选链路见 [04-权限与菜单](./04-权限与菜单.md)。

### 4.3 数据权限（DataScope）

`Features:DataScope` 开启后，按角色 `DataScope` 过滤可见行：

| 值 | 含义 |
|----|------|
| 0 | 全部 |
| 1 | 本部门 |
| 2 | 本部门及下级 |
| 3 | 仅本人 |

注入 `IDataScopeService`：

- `GetAllowedUserIdsAsync`：空集合表示全部（不过滤）
- `FilterByCreateIds` / `ApplyCreateIdScopeAsync`：按 `BaseEntity.CreateId` 过滤业务表
- `FilterUsersByAllowedIds`：用户列表
- `FilterLogsByUserIds`：日志按 `User_Id`

业务 Service 需**主动调用**过滤（如 `SysDeviceService`），不是全局 EF 过滤器。

### 4.4 多租户（与 DataScope 独立）

生效条件：`Features:Tenant=true` **且** `Tenant:Enabled=true`。

- `BaseEntity.TenantId`；`TenantId = 0` 视为公共数据
- Program 中租户中间件设置 `SevenDbContext` 的全局 QueryFilter
- **未实现**：多库、动态连接串、按 Schema 隔离

## 5. EF Core 用法与原理

### 5.1 BaseEntity

```csharp
// Seven.Domain/Common/BaseEntity.cs
public abstract class BaseEntity : ISoftDelete
{
    public int TenantId { get; set; }
    public int? CreateId { get; set; }
    public string? Creator { get; set; }
    public DateTime? CreateDate { get; set; }
    public int? ModifyId { get; set; }
    public string? Modifier { get; set; }
    public DateTime? ModifyDate { get; set; }
    public bool IsDeleted { get; set; }
}
```

业务主键（如 `DeviceId`）在实体上单独声明，不放在基类。

### 5.2 全局查询过滤器

`SevenDbContext.OnModelCreating` 对所有 `BaseEntity`：

1. **软删除**：`IsDeleted == false`（删除应设 `IsDeleted = true`，勿物理删）
2. **租户**：过滤器关闭，或 `TenantId == 0`，或 `TenantId == CurrentTenantId`

列表查询习惯使用 `AsNoTracking()`；写操作保持跟踪。

### 5.3 Fluent 配置 + Migration

配置类放在 `Seven.Infrastructure/Persistence/Configurations`，实现 `IEntityTypeConfiguration<T>`，在 DbContext 中 `ApplyConfigurationsFromAssembly`（或显式注册）。

```bash
cd Seven.Master/Seven.Net8
dotnet ef migrations add AddXxx --project Seven.Infrastructure --startup-project Seven.WebApi
dotnet ef database update --project Seven.Infrastructure --startup-project Seven.WebApi
```

`Database:Provider`：`MySql` / `SqlServer` / `PgSql`。开发可设 `MigrateOnStartup: true`。

### 5.4 CrudHelper 分页协议

前端/生成页 POST body 使用 `PageDataOptions`（页码、排序、`Wheres` JSON）。Service 典型写法：

```csharp
public async Task<PageGridData<Device>> GetPageDataAsync(PageDataOptions options, CancellationToken ct)
{
    var query = _db.Devices.AsNoTracking();
    query = _dataScope.FilterByCreateIds(query, await _dataScope.GetAllowedUserIdsAsync(ct));
    return await CrudHelper.PaginateAsync(query, options, ct);
}
```

`CrudHelper` 定义在 `AuthService.cs` 同文件静态类中（历史位置），支持 equal/like 等 `displayType`。

### 5.5 审计拦截器

`Features.AuditInterceptor=true` 时注册 `AuditSaveChangesInterceptor`：SaveChanges 时把实体字段变更写入 `Sys_Log`（LogType=Audit）。

注意：拦截器**不自动填充** `CreateId` / `ModifyId`，需在 Service 的 Add/Update 中赋值（可注入 `ICurrentUserService`）。

### 5.6 与架构文档的差异

未引入 Repository、UnitOfWork、Specification、LazyLoading、通用并发令牌。并发控制按业务需要自行加行版本字段。

## 6. 缓存

### 6.1 选型与注册

`Cache:Provider = Memory | Redis`。无论哪种，外层均装饰为 `DelayedDoubleDeleteCacheService`。

接口：`ICacheService`（`Seven.Application`）。

### 6.2 延迟双删（原理）

写多读少场景下，避免「删缓存后、旧请求又把脏数据写回缓存」：

```
更新 DB → 删除缓存 → 延迟 DelayedDeleteMs（默认 500ms）→ 再删一次
```

用法：写操作后调用：

```csharp
await _cache.RemoveWithDelayedDoubleDeleteAsync($"user:{id}");
// 或依赖装饰器：RemoveAsync 也会走延迟双删
```

已用场景：用户/角色/菜单树/部门树/字典等（见 `SystemServices.cs`）。菜单读侧为 Cache-Aside：先 Get，miss 再查库 Set。

另：Refresh Token、验证码、幂等 Key 也走同一 `ICacheService`。

### 6.3 HotStore

高频运营数据（路径/流量等）与主数据缓存职责分离，见 [15-热数据HotStore](./15-热数据HotStore.md)。

**未实现**：通用两级缓存抽象、分布式锁组件、击穿/穿透/雪崩专用治理。

## 7. 新增业务模块流程

以仓库 Demo [`Device.cs`](../Seven.Net8/Seven.Domain/Entities/Business/Device.cs) 为模板。也可开启 `Features.Builder` 用代码生成器（见 [06-代码生成器](./06-代码生成器.md)）。

### 7.1 定义实体（Seven.Domain）

| 项 | 说明 |
|----|------|
| 路径 | 业务：`Entities/Business/`；系统：`Entities/System/` |
| 基类 | **必须**继承 `BaseEntity` |
| 主键 | 业务主键单独声明（如 `DeviceId`） |
| 字符串 | 必填 `string` + `= string.Empty`；可空 `string?` |
| 枚举列 | 库存 `int`，标 `[FormEnum(typeof(XxxStatus))]` |
| 注释 | 类与 public 属性写 `/// <summary>` |

```csharp
using Seven.Domain.Attributes;
using Seven.Domain.Common;
using Seven.Domain.Enums;

namespace Seven.Domain.Entities.Business;

/// <summary>设备信息（业务模块 Demo）</summary>
public class Device : BaseEntity
{
    /// <summary>设备 Id</summary>
    public int DeviceId { get; set; }

    /// <summary>设备名称</summary>
    public string DeviceName { get; set; } = string.Empty;

    /// <summary>设备编码</summary>
    public string? DeviceCode { get; set; }

    /// <summary>设备状态</summary>
    [FormEnum(typeof(DeviceStatus))]
    public int Status { get; set; }

    /// <summary>位置</summary>
    public string? Location { get; set; }
}
```

枚举放在 `Seven.Domain/Enums`，成员建议加 `[Description("显示名")]`。一对多子表同目录声明，外键指向主表主键。

### 7.2 EF 配置 + DbSet + Migration

```csharp
public class DeviceConfiguration : IEntityTypeConfiguration<Device>
{
    public void Configure(EntityTypeBuilder<Device> builder)
    {
        builder.ToTable("Device");
        builder.HasKey(x => x.DeviceId);
        builder.Property(x => x.DeviceName).HasMaxLength(128).IsRequired();
        builder.Property(x => x.DeviceCode).HasMaxLength(64);
        builder.Property(x => x.Location).HasMaxLength(256);
    }
}
```

在 `SevenDbContext` 增加 `DbSet<Device>`，再执行 §5.3 的 migration 命令。

### 7.3 应用服务与 Controller

| 层 | 位置 |
|----|------|
| 接口 | `Seven.Application`（如 `ISysDeviceService`） |
| 实现 | `Seven.Infrastructure.Services` 或 `Seven.Business` |
| API | `[Authorize]` + `[Permission("Device.Search")]` 等；可选 `[RequiresFeature]` |

约定路由风格（兼容 Legrand）：`/api/{TableName}/getPageData|getDetail|add|update|del`。

`Sys*Service` 可通过程序集约定自动注册为对应 `I*` 接口（见 `AddSevenInfrastructure`）。手写 Controller 参考 `Sys_UserController`；生成结果参考 `Controllers/Generated/DeviceController.cs`。

新增菜单与角色授权后，前端才能看到页面与按钮（见 [04](./04-权限与菜单.md)）。

### 7.4 清单

1. Domain 实体 + 枚举  
2. Fluent 配置 + DbSet + Migration  
3. Application 接口 + Infrastructure 实现（分页、软删、审计字段、可选缓存双删 / DataScope）  
4. Controller + Permission  
5. 菜单 Auth / 角色授权  
6. 前端页面或 Builder 生成页 + extension（见前端指南）

## 8. 统一响应

所有业务 API 返回 `WebResponseContent`：

```json
{ "status": true, "message": "操作成功", "data": {}, "code": null }
```

前端 Axios 已按 `status === false` 统一 Toast（登录等白名单除外）。新接口勿改成另一套信封格式。

## 9. 中间件与 Filter 速查

| 类型 | 用途 | 文件 |
|------|------|------|
| 异常 / TraceId / 请求日志 | 横切 | `Middleware/SevenMiddleware.cs` |
| 幂等 + IP 白名单 | 安全 | `Middleware/IdempotencyMiddleware.cs` |
| `[RequiresFeature]` | 功能关闭 → 404 | `Security/RequiresFeatureAttribute.cs` |
| `[Permission]` | 接口授权 | `Security/PermissionAuthorization.cs` |

异常由中间件处理，未使用全局 ExceptionFilter。限流、CORS、压缩用 ASP.NET Core 内置中间件。更多安全项见 [13-安全与数据权限](./13-安全与数据权限.md)。
