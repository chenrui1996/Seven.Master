# 后端开发指南

## 分层与依赖

```
Seven.WebApi          → Controllers、Hubs、Program、Swagger、健康检查
Seven.Application     → 服务接口、DTO、消息契约（无基础设施依赖）
Seven.Domain          → 实体、枚举、BaseEntity、WebResponseContent
Seven.Infrastructure  → EF、缓存、JWT、安全、MQ、Quartz、存储、邮件、中间件
Seven.Business        → 业务域服务（如工作流引擎）
Seven.Builder         → 代码生成器实现
Seven.Tests           → 单元 / 集成测试
```

依赖方向：`WebApi → Application → Domain ← Infrastructure / Business / Builder`

## 解决方案项目职责

| 项目 | 职责 |
|------|------|
| **Seven.Domain** | 纯领域模型：`Entities/*`、`Enums`、`Common`（`BaseEntity`、`ISoftDelete`、统一响应） |
| **Seven.Application** | 应用层契约：`I*Service`、请求/响应模型、MQ 事件定义；不引用 EF |
| **Seven.Infrastructure** | 技术实现与横切：DbContext、种子、缓存、认证授权、限流/防重、文件、邮件、MassTransit、Quartz、Options |
| **Seven.Business** | 可独立演进的业务服务（当前含 `WorkFlowService`），由 `AddSevenBusiness()` 注册 |
| **Seven.Builder** | 读表结构、生成 Entity/Service/Controller/Vue 模板代码 |
| **Seven.WebApi** | HTTP 入口：`Program.cs`、Controllers、SignalR Hubs、生成模板 `Template/`、`Generated/` |
| **Seven.Tests** | FluentAssertions + WebApplicationFactory 等 |

| 目录 | 说明 |

| `Messaging/` | MassTransit、Consumer、Outbox |

## 新增业务模块流程

### 1. 定义实体（Seven.Domain）

以仓库内业务 Demo [`Device.cs`](../Seven.Net8/Seven.Domain/Entities/Business/Device.cs) 为模板。

#### 约定

| 项 | 说明 |
|----|------|
| 放置路径 | 业务实体：`Seven.Domain/Entities/Business/`；系统实体：`Entities/System/` 等 |
| 命名空间 | `Seven.Domain.Entities.Business` |
| 基类 | **必须**继承 `BaseEntity`（提供 `TenantId`、创建/修改审计、`IsDeleted` 软删除） |
| 主键 | 业务主键字段单独声明（如 `DeviceId`），不放在基类 |
| 字符串 | 必填用 `string` + `= string.Empty`；可空用 `string?` |
| 枚举列 | 库中存 `int`，属性标 `[FormEnum(typeof(XxxStatus))]`，供生成页/表单识别选项 |
| 注释 | 类与 public 属性写 `/// <summary>` |

`BaseEntity` 已含字段（无需在业务实体重复声明）：`TenantId`、`CreateId`、`Creator`、`CreateDate`、`ModifyId`、`Modifier`、`ModifyDate`、`IsDeleted`。

#### 示例（与 `Device` 一致）

```csharp
using Seven.Domain.Attributes;
using Seven.Domain.Common;
using Seven.Domain.Enums;

namespace Seven.Domain.Entities.Business;

/// <summary>
/// 设备信息（业务模块 Demo）
/// </summary>
public class Device : BaseEntity
{
    /// <summary>设备 Id</summary>
    public int DeviceId { get; set; }

    /// <summary>设备名称</summary>
    public string DeviceName { get; set; } = string.Empty;

    /// <summary>设备编码</summary>
    public string? DeviceCode { get; set; }

    /// <summary>设备状态</summary>
    [FormEnum(typeof(DeviceStatus))]
    public int Status { get; set; }

    /// <summary>位置</summary>
    public string? Location { get; set; }
}
```

枚举放在 `Seven.Domain/Enums`（如 `DeviceStatus`），成员建议加 `[Description("显示名")]`，便于前端/字典展示。

一对多子表同文件或同目录声明即可，外键指向主表主键（参考同文件中的 `SubDevice.DeviceId`）。

### 2. EF 配置 + DbSet + Migration

在 `Seven.Infrastructure/Persistence/Configurations` 增加 `IEntityTypeConfiguration<T>`（参考 `DeviceConfiguration` / `SubDeviceConfiguration`）：

```csharp
public class DeviceConfiguration : IEntityTypeConfiguration<Device>
{
    public void Configure(EntityTypeBuilder<Device> builder)
    {
        builder.ToTable("Device");
        builder.HasKey(x => x.DeviceId);
        builder.Property(x => x.DeviceName).HasMaxLength(128).IsRequired();
        builder.Property(x => x.DeviceCode).HasMaxLength(64);
        builder.Property(x => x.Location).HasMaxLength(256);
    }
}
```

在 `SevenDbContext` 增加 `DbSet<Device>`，然后执行：

```bash
cd Seven.Master/Seven.Net8
dotnet ef migrations add AddDevice --project Seven.Infrastructure --startup-project Seven.WebApi
dotnet ef database update --project Seven.Infrastructure --startup-project Seven.WebApi
```

### 3. 应用服务与 Controller

- 接口：`Seven.Application`
- 实现：`Seven.Infrastructure.Services`（如现有 `SysDeviceService`）或 `Seven.Business`
- API：`[Authorize]` + `[Permission("Device.Search")]` 等；可选 `[RequiresFeature]`

或使用 **Builder** 生成 CRUD（需 `Features.Builder=true`），生成结果对照 `Seven.WebApi/Controllers/Generated/DeviceController.cs`。

## 统一响应

所有 API 返回 `WebResponseContent`：

```json
{ "status": true, "message": "操作成功", "data": {}, "code": null }
```

## 缓存 / 热数据 / 密码

- 缓存：`ICacheService`；写后可用延迟双删（菜单/字典等读多写少）
- 热数据：`IHotStore`（`Features.HotStore`）；路径/流量等高频读写  
  - 实现思路（热冷分层、预热/落库、代码位置）与接入步骤见 [15-热数据HotStore](./15-热数据HotStore.md)  
  - DI：`AddSevenHotStore`；扩展点：`IHotStoreWarmup` / `IHotStorePersister`
- 密码：仅 `IPasswordHasher`（BCrypt），禁止明文/对称可逆存储

## 中间件顺序（摘要）

Exception → TraceId → RequestLog → IpWhitelist → Idempotency(可选) → Compression → RateLimiter → AuthN → AuthZ → 租户上下文 → Controllers / Hubs

## 日志

系统里有两套日志，用途不同：

### 1. 业务/审计日志（`Sys_Log`，页面可查）

| 项 | 位置 |
|----|------|
| 前端 | **系统管理 → 日志管理**，路由 `/Sys_Log`，页面 `Seven.Vue3/src/views/system/Sys_Log.vue` |
| API | `POST /api/Sys_Log/getPageData`（权限 `Sys_Log.Search`） |
| 服务 | `SysLogService`（`Seven.Infrastructure/Services/SystemServices.cs`） |
| 实体/表 | `Sys_Log`（`Seven.Domain/Entities/System`） |
| 写入来源 | 登录等业务写入；开启 `Features.AuditInterceptor` 时由 `AuditSaveChangesInterceptor` 记录实体字段变更 |

### 2. 运行时日志（Serilog）

| 项 | 位置 |
|----|------|
| 配置 | `Seven.WebApi/Program.cs`：`WriteTo.Console` + `WriteTo.File("logs/seven-.log", rollingInterval: Day)` |
| 文件目录 | 一般为 `Seven.Net8/Seven.WebApi/logs/seven-YYYYMMDD.log`（相对 API 进程工作目录） |
| 控制台 | `dotnet run --project Seven.WebApi` 的终端输出 |

Docker 部署时文件在容器内工作目录的 `logs/`；可用 `docker compose logs seven-api` 看控制台流。
