# 告警模块指南

Seven.Master 告警模块采用 **后端抛出 + 数据库持久化 + SignalR 实时推送 + 前端角标/列表** 的实现方式。

## 架构概览

```
业务代码 / 设备联机
    ↓ IAlarmService.RaiseAsync(code)
报警码解析（Sys_AlarmCode 或 appsettings）
    ↓
写入 Sys_Alarm 表
    ↓ IAlarmPushService
SignalR /hub/alarm → ReceiveAlarm
    ↓
前端 AlarmBell 角标 + Sys_Alarm 列表
```

## 如何配置报警码

报警码是告警的**唯一标识**，抛出时通过 Code 查找对应的**默认消息、级别、分类**。

支持 **两种方式**（优先级：数据库 > appsettings）：

### 方式一：appsettings.json（推荐初始/部署配置）

在 `Seven.WebApi/appsettings.json` 的 `Alarm:Codes` 节点配置：

```json
{
  "Alarm": {
    "Codes": [
      {
        "Code": "WCS001",
        "Message": "设备 {DeviceName} 通信超时",
        "Level": 3,
        "Category": "WCS",
        "Remark": "WCS 设备通信异常"
      },
      {
        "Code": "WMS001",
        "Message": "库位 {Location} 库存异常",
        "Level": 2,
        "Category": "WMS"
      }
    ]
  }
}
```

| 字段 | 说明 |
|------|------|
| `Code` | 报警码，全局唯一，建议 `模块+序号`（如 WCS001） |
| `Message` | 报警信息模板，支持占位符 |
| `Level` | 1 信息 / 2 警告 / 3 错误 / 4 严重 |
| `Category` | 分类：WMS、WCS、Device、System |
| `Remark` | 备注说明 |

**启动行为**：`DbSeeder` 会将 appsettings 中的报警码同步到 `Sys_AlarmCode` 表（已存在的 Code 跳过）。

### 方式二：数据库 / 管理界面（推荐运行时维护）

登录系统 → **告警管理** → **报警码** 标签页，可新增、编辑报警码。

也可直接操作 `Sys_AlarmCode` 表：

| 列 | 说明 |
|----|------|
| Code | 报警码 |
| Message | 信息模板 |
| Level | 级别 1-4 |
| Category | 分类 |
| Enable | 1 启用 / 0 禁用 |

## 如何配置报警信息

报警信息由 **模板 + 运行时参数** 组成。

### 模板占位符

| 占位符 | 来源 |
|--------|------|
| `{DeviceName}` | `RaiseAlarmRequest.DeviceName` |
| `{Source}` | `RaiseAlarmRequest.Source` |
| `{Code}` | 报警码本身 |
| `{自定义键}` | `RaiseAlarmRequest.Params` 字典 |

示例模板：

```
设备 {DeviceName} 通信超时
库位 {Location} 库存异常
```

未替换的占位符会显示为 `—`。

### 级别说明

| Level | 枚举 | 前端展示 |
|-------|------|----------|
| 1 | Info | 信息（蓝色） |
| 2 | Warning | 警告（橙色） |
| 3 | Error | 错误（红色） |
| 4 | Critical | 严重（红色） |

## 后端如何抛出告警

### 1. 注入 IAlarmService

```csharp
public class YourWcsService
{
    private readonly IAlarmService _alarm;

    public YourWcsService(IAlarmService alarm) => _alarm = alarm;

    public async Task OnDeviceTimeout(string deviceName)
    {
        await _alarm.RaiseAsync(new RaiseAlarmRequest
        {
            Code = "WCS001",
            Source = "WcsScheduler",
            DeviceName = deviceName,
            Params = new Dictionary<string, string>
            {
                ["DeviceName"] = deviceName
            }
        });
    }
}
```

抛出后会自动：

1. 解析报警码与模板
2. 写入 `Sys_Alarm` 表（Status = 活跃）
3. 通过 SignalR 广播 `ReceiveAlarm` 事件
4. 发布 `AlarmRaisedEvent` 到 RabbitMQ（`MessageQueue:Provider=RabbitMQ` 时）

### 4. 消息队列入站（WCS 推荐）

WCS/边缘系统可发布 `RaiseAlarmCommand` 到 RabbitMQ，由 `AlarmRaiseConsumer` 自动调用 `RaiseAsync`：

```http
POST /api/MessageQueue/publishRaiseAlarm
{
  "code": "WCS001",
  "source": "WcsEdge",
  "deviceName": "Stacker-01"
}
```

详见 **[10-消息队列指南](./10-消息队列指南.md)**。

### 2. HTTP API（测试 / 外部系统）

```http
POST /api/Sys_Alarm/raise
Authorization: Bearer {token}
Content-Type: application/json

{
  "code": "WCS001",
  "source": "ExternalApi",
  "deviceName": "Stacker-01",
  "params": { "DeviceName": "Stacker-01" }
}
```

权限：`Sys_Alarm.Raise`

### 3. 确认与清除

```http
POST /api/Sys_Alarm/acknowledge
Body: [1, 2, 3]

POST /api/Sys_Alarm/clear
Body: [1, 2, 3]
```

权限：`Sys_Alarm.Acknowledge`、`Sys_Alarm.Clear`

## 前端如何显示

### 实时推送

登录后主布局自动连接 `/hub/alarm`（JWT 通过 `access_token` 查询参数传递）。

| SignalR 事件 | 说明 |
|--------------|------|
| `ReceiveAlarm` | 新告警，角标 +1，弹层列表更新 |
| `AlarmUpdated` | 确认/清除后状态变更 |

### 页面入口

- 顶栏 **AlarmBell** 铃铛图标（带活跃数角标）
- 侧边栏 **告警管理**（`/Sys_Alarm`）
- 首页 KPI「活跃告警」卡片（实时数量）
- 首页「告警中心」快捷入口

## 已有数据库升级

项目已使用 **EF Core Migrations**。新环境执行 `dotnet ef database update` 或启动 API 即可自动迁移。

若数据库来自早期 **EnsureCreated** 版本（无 `__EFMigrationsHistory`）：

1. **开发环境**：删库后重新 `database update`（推荐）
2. **生产环境**：由 DBA 评估 baseline 或手工补迁移历史
3. **菜单/权限**：若缺少「告警管理」，在菜单管理中补录 `Url=/Sys_Alarm`，`TableName=Sys_Alarm`

新库首次启动会自动迁移、Seed 菜单，并同步 appsettings 中的报警码。
