# 消息队列指南

> 需同时 `Features:MessageQueue=true` 且 `MessageQueue:Provider=RabbitMQ`。Outbox 另需 `Features:Outbox=true`。见 [14-功能开关](./14-功能开关.md)。

Seven.Master 采用 **RabbitMQ + MassTransit** 作为消息队列方案。这是 .NET 企业级项目的主流组合：RabbitMQ 负责可靠消息中间件，MassTransit 提供统一的发布/订阅、Consumer、重试与端点配置。

## 为什么选 RabbitMQ

| 对比 | RabbitMQ + MassTransit | Redis Streams | Kafka |
|------|------------------------|---------------|-------|
| .NET 生态 | MassTransit 成熟 | 需自研封装 | Confluent 客户端，运维较重 |
| 与 Seven 架构 | 对齐 `系统架构设计.md` | 与缓存职责混杂 | Legrand 遗留已注释 |
| 部署 | Docker 单容器即可 | 已有 Redis | 集群成本高 |
| 适用场景 | WCS 告警、异步任务、系统集成 | 轻量队列 | 超高吞吐日志流 |

本地开发可设 `Provider: None`，**零依赖**运行；Docker Compose 一键启用 RabbitMQ。

## 架构

```
┌─────────────┐     RaiseAlarmCommand      ┌──────────────┐
│ WCS / 边缘   │ ─────────────────────────► │  RabbitMQ    │
└─────────────┘                             └──────┬───────┘
                                                   │
                     AlarmRaiseConsumer            │
                     IAlarmService.RaiseAsync      ▼
┌─────────────┐     AlarmRaisedEvent       ┌──────────────┐
│ MES / 监控   │ ◄───────────────────────── │  Seven API   │
└─────────────┘                             └──────┬───────┘
                                                   │ SignalR
                                                   ▼
                                            前端 AlarmBell
```

### 消息契约

| 类型 | 方向 | 说明 |
|------|------|------|
| `RaiseAlarmCommand` | 入站 | WCS/PLC 请求抛警 |
| `AlarmRaisedEvent` | 出站 | 告警已落库，外部系统订阅 |

定义位置：`Seven.Application/Messaging/MessageContracts.cs`

## 配置

### appsettings.json

```json
{
  "MessageQueue": {
    "Provider": "None",
    "EnableConsumers": true,
    "RabbitMq": {
      "Host": "localhost",
      "Port": 5672,
      "VirtualHost": "/",
      "Username": "guest",
      "Password": "guest"
    }
  }
}
```

| 字段 | 说明 |
|------|------|
| `Provider` | `None`（禁用）或 `RabbitMQ` |
| `EnableConsumers` | 是否在 API 进程内注册 MassTransit Consumer |
| `RabbitMq.*` | RabbitMQ 连接参数 |

### Provider 切换（仿 Cache 模式）

| 环境 | Provider | 说明 |
|------|----------|------|
| 本地开发 | `None` | 不连 RabbitMQ，发布操作为 NoOp |
| Docker Compose | `RabbitMQ` | 自动连接 `rabbitmq` 服务 |
| 单元测试 | `None` | `appsettings.Testing.json` 已配置 |

### Docker Compose

`docker-compose.yml` 已包含：

| 服务 | 端口 | 说明 |
|------|------|------|
| `rabbitmq` | 5672 | AMQP |
| 管理界面 | 15672 | http://localhost:15672 （guest/guest） |

启动：

```bash
cd Seven.Master
docker compose up -d
```

`seven-api` 环境变量：

```
MessageQueue__Provider=RabbitMQ
MessageQueue__RabbitMq__Host=rabbitmq
```

## 后端使用

### 1. 发布消息（出站）

注入 `IMessagePublisher`：

```csharp
await _publisher.PublishAsync(new AlarmRaisedEvent
{
    AlarmId = 1,
    Code = "WCS001",
    Message = "设备通信超时",
    Level = 3,
    OccurredAt = DateTime.Now
});
```

告警模块已在 `AlarmService.RaiseAsync` 成功后自动发布 `AlarmRaisedEvent`。

### 2. 消费消息（入站）

`AlarmRaiseConsumer` 已实现：收到 `RaiseAlarmCommand` → 调用 `IAlarmService.RaiseAsync`。

新增 Consumer 步骤：

1. 在 `MessageContracts.cs` 定义消息类型
2. 在 `Infrastructure/Messaging/Consumers/` 实现 `IConsumer<T>`
3. 在 `MessageQueueServiceCollectionExtensions` 中 `x.AddConsumer<YourConsumer>()`

### 3. HTTP 测试 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/MessageQueue/status` | 查看 Provider、RabbitMQ 连接信息 |
| POST | `/api/MessageQueue/publishRaiseAlarm` | 发布 `RaiseAlarmCommand` 到队列 |

示例：

```http
POST /api/MessageQueue/publishRaiseAlarm
Authorization: Bearer {token}
Content-Type: application/json

{
  "code": "WCS001",
  "source": "WcsSimulator",
  "deviceName": "Stacker-01",
  "params": { "DeviceName": "Stacker-01" }
}
```

Consumer 处理后触发完整告警链路：DB → SignalR → `AlarmRaisedEvent` 出站。

## 与告警模块集成

详见 [09-告警模块.md](./09-告警模块.md)。

| 路径 | 触发方式 |
|------|----------|
| HTTP | `POST /api/Sys_Alarm/raise` |
| MQ 入站 | 发布 `RaiseAlarmCommand` |
| MQ 出站 | 订阅 `AlarmRaisedEvent` |

推荐 WCS/边缘系统走 **MQ 入站**，MES/监控走 **AlarmRaisedEvent 出站**，UI 实时仍由 **SignalR** 负责。

## 扩展建议

1. **Outbox 模式**：事务与发消息原子性（架构文档第 13 章）
2. **独立 Worker**：Consumer 从 API 进程拆到 `Seven.Worker` 项目
3. **死信队列**：MassTransit 内置 `_error` 队列，可配置重试策略
4. **新消息类型**：仓储任务、设备状态变更等，复用 `IMessagePublisher` + Consumer 模式

## 故障排查

| 现象 | 处理 |
|------|------|
| API 启动报 RabbitMQ 连接失败 | 检查 `Provider` 是否为 `RabbitMQ` 且 RabbitMQ 已启动 |
| 本地不想装 RabbitMQ | 设 `MessageQueue:Provider` 为 `None` |
| 消息发布无效果 | `None` 模式下 NoOp 不发送；确认 Provider 与 Consumer |
| 管理界面 | http://localhost:15672 guest/guest |
