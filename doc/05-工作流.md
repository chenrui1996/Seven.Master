# 工作流

> 需开启 `Features:WorkFlow=true`（见 [14-功能开关](./14-功能开关.md)），否则 API 返回 404，前端不显示流程菜单。

## 概述

Seven 对齐 Legrand 审批工作流：线性多步审批 + 可视化步骤设计（`NodeConfig`/`LineConfig`）+ 单据审批进度查看。条件分支字段已预留，引擎仍按 `StepOrder` 线性推进。

## 核心表

| 表 | 说明 |
|----|------|
| Sys_WorkFlow | 流程定义（含 NodeConfig、LineConfig、Weight、AuditingEdit） |
| Sys_WorkFlowStep | 流程步骤（StepId、StepAttrType、NextStepIds 等可视化元数据） |
| Sys_WorkFlowTable | 流程实例 |
| Sys_WorkFlowTableStep | 实例步骤状态（含 StepName/Auditor 快照） |
| Sys_WorkFlowTableAuditLog | 审批日志 |

## 业务表要求

需要走审批的业务表必须包含 `AuditStatus` 字段：

| 值 | 含义 |
|----|------|
| 0 | 待审核 |
| 1 | 审核通过 |
| 2 | 审核中 |
| 3 | 审核未通过 |
| 4 | 驳回 |

## API

| 接口 | 说明 |
|------|------|
| POST /api/Sys_WorkFlow/listDefinitions | 流程列表 |
| POST /api/Sys_WorkFlow/getDefinition | 流程详情（含步骤） |
| POST /api/Sys_WorkFlow/saveDefinition | 保存流程 + 步骤 + 可视化 JSON |
| POST /api/Sys_WorkFlow/delete | 删除流程定义 |
| POST /api/Sys_WorkFlow/submit | 提交审批 |
| POST /api/Sys_WorkFlow/audit | 审批（通过/驳回/拒绝） |
| POST /api/Sys_WorkFlow/getSteps | 单据审批进度（对齐 Legrand getSteps） |
| GET /api/Sys_WorkFlow/getNodeDic | 审批人字典（用户/角色/部门） |
| POST /api/Sys_WorkFlowTable/getPageData | 待办/已办（wheres scope=`todo`\|`done`） |

同表多流程时按 `Weight` 降序优先匹配。

## 配置流程

1. 工作流管理 → 新建流程，绑定业务表 `WorkTable`
2. 可视化设计器添加步骤（角色/用户/部门），上下调整顺序
3. 保存后 `NodeConfig`/`LineConfig` 自动写入
4. 业务页通过 `hooks.submitAudit` 提交；CrudPanel 对含 `auditStatus` 的行显示「审批进度」

## 生成页接入 submitAudit

在业务表的 `*.extension.ts` 中通过 `hooks.submitAudit` 提交审批（或由 CrudPanel 在配置了该钩子时自动显示「提交审批」行按钮）：

```ts
import type { PageExtension } from '@/extension/types'
import http from '@/api/http'
import { ElMessage } from 'element-plus'

const extension: PageExtension = {
  hooks: {
    submitAudit: async ({ row, tableName }) => {
      const tableKey = String(row.id ?? '')
      if (!tableKey) {
        ElMessage.warning('无法识别业务主键')
        return
      }
      const res = await http.post('/api/Sys_WorkFlow/submit', { tableName, tableKey })
      if (res.status) ElMessage.success('已提交审批')
    },
  },
}

export default extension
```

说明：`tableName` 须与流程定义中的 `WorkTable` 一致；`tableKey` 为业务主键值的字符串形式。主键列名在流程定义的 `WorkTableKey` 中配置。

## 步骤审批人类型（StepType）

| 值 | 含义 |
|----|------|
| 1 | 角色（StepValue=角色Id，逗号分隔） |
| 2 | 用户（StepValue=用户Id） |
| 3 | 部门（StepValue=部门Id） |

## 条件分支与会签

- **进入条件 Filters**：步骤可配置字段条件 JSON（`[{ field, filterType, value }]`）。提交/流转时加载业务行，仅命中条件的步骤可进入；无条件视为全匹配。
- **会签 AuditMethod=1**：`StepValue` 填多个用户 Id，全部通过后才进入下一步；中途拒绝仍结束流程。
- 设计器：步骤属性中可编辑条件行与会签开关。

## 表单设计

- 菜单「表单设计」→ `FormDesignOptions`：配置字段 JSON，支持预览填报与采集记录查询。
- API：`/api/FormDesignOptions/*`

## 个人中心

- 头像菜单 →「个人中心」`/UserInfo`：改资料、上传头像、改密。
