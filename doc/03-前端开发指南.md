# 前端开发指南

本文说明 Seven.Vue3 的启动流程、登录与 Token、动态路由、Pinia、Axios、权限、主题/i18n，以及生成页扩展入口。对照 [系统架构设计.md](../../系统架构设计.md) 第二章：只写**已落地**行为；未做的「配置 Store / 完整面包屑 / 前端 Policy」等会标明。

环境与启动见 [01-快速开始](./01-快速开始.md)。权限配置见 [04-权限与菜单](./04-权限与菜单.md)。功能裁剪见 [14-功能开关](./14-功能开关.md)。

## 1. 技术栈与目录

### 1.1 技术栈

- Vue 3 + Composition API + TypeScript
- Vite
- Pinia（含 `pinia-plugin-persistedstate`）
- Vue Router 4（动态路由）
- Element Plus
- Axios（Token 自动刷新、业务失败 Toast）
- vue-i18n
- SignalR（告警 / 系统通知 / DeviceComm 运行态，受 Features 控制）

### 1.2 目录结构

```
Seven.Vue3/
├── src/
│   ├── api/            # Axios 封装、登录/菜单/字典/上传等
│   ├── assets/         # 图标、背景图案
│   ├── components/     # 公共组件（CrudPanel、AlarmBell、主题/语言切换）
│   ├── composables/    # useAlarmHub、useMessageHub、表格列等
│   ├── constants/      # 操作图标映射
│   ├── directives/     # v-permission
│   ├── extension/      # 生成页扩展（hooks/按钮，不被生成覆盖）
│   ├── layout/         # MainLayout（侧栏、标签、KeepAlive）
│   ├── locales/        # i18n 语言包与 Element Plus 本地化
│   ├── router/         # 路由、动态注册、权限守卫
│   ├── stores/         # user / menu / tabs / dict / theme / locale / features / alarm
│   ├── styles/         # 主题与按钮样式
│   ├── utils/          # 菜单树、主题、namedRouteComponent
│   ├── views/          # 页面（system/*、Business/*、DeviceComm/*、Login、Home）
│   ├── App.vue
│   └── main.ts         # 启动时拉取 Features
├── docker/             # 前端镜像用 nginx 配置
├── Dockerfile
├── vite.config.ts
└── package.json
```

| 路径 | 说明 |
|------|------|
| `views/system/` | 系统管理页（用户/角色/菜单/字典/日志/工作流/Quartz…） |
| `views/system/Sys_Log.vue` | 日志管理；菜单「系统管理 → 日志管理」 |
| `views/Business/` | 业务生成页入口（如 Device） |
| `views/DeviceComm/` | 设备通讯：连接/点位/规则/运行态（需 `Features.DeviceComm`） |
| `components/crud/` | 通用 CRUD 面板与扩展合并 |
| `extension/Business/` | 业务页自定义按钮与 hooks |
| `extension/DeviceComm/` | 通讯页扩展（如规则触发） |
| `stores/features.ts` | 功能开关；过滤菜单、控制验证码/Hub |

运行时 Serilog 文件日志不在前端查看，见 [01 §6](./01-快速开始.md#6-如何查看日志)。

### 1.3 环境变量

`.env.development`：

```
VITE_API_BASE_URL=http://localhost:5000
```

生产构建由部署环境注入同名变量；Axios `baseURL` 与 SignalR 连接均依赖它。

## 2. 启动流程（原理）

`src/main.ts` 顺序：

```
createPinia + persistedstate
  → app.use(pinia)
  → app.use(i18n)
  → themeStore.init() / localeStore.init()
  → await featureStore.load()          // GET /api/config/features
  → app.use(router)
  → Element Plus + v-permission
  → mount
```

**为何先拉 Features**：登录页是否显示验证码、侧栏是否裁剪工作流/Quartz 菜单、是否连接 Hub，都依赖开关。失败时用 `features.ts` 内默认值，避免阻塞启动。

`index.html` 内联脚本会提前读 localStorage 的 `theme`，减少首屏闪烁。`App.vue` 用 `el-config-provider` 绑定 Element Plus 语言包。

## 3. 登录与 Token

### 3.1 数据流

```
Login.vue
  → POST /api/Auth/login
  → userStore.setToken + setUserInfo（含 permissions）
  → router.push('/home')
  → 守卫拉菜单 → 动态路由
```

| 文件 | 职责 |
|------|------|
| `views/Login.vue` | 表单；`featureStore.captchaEnabled` 时拉验证码 |
| `stores/user.ts` | Token、用户信息、权限、`hasPermission` / `refreshPermissions` |
| `api/http.ts` | Bearer、401 刷新队列、业务失败 Toast |

### 3.2 持久化策略（原理）

Pinia persist **只**保存：`token`、`refreshToken`、`userId`、`userName`、`userTrueName`、`roleId`。

**不持久化 `permissions`**：进入系统时守卫调用 `GET /api/Auth/permissions` 刷新，避免本地缓存导致已收回的按钮仍显示。

`isLoggedIn` 仅看是否有 Access Token。刷新页面后菜单会重新拉取；标签页状态**不**持久化（刷新会丢 tab）。

没有独立的「记住我」或 OAuth 登录；架构文档中的 Cookie / OAuth2 未做。

### 3.3 Access / Refresh（用法）

1. 请求拦截器附加 `Authorization: Bearer {token}`；若已有 token（如重新登录后），重置 `isRedirectingToLogin`，避免防重入标志残留
2. 收到 **HTTP 401**：
   - 无 refresh → 提示 `login.expired` → `logout` → `router.replace('/login')`（防重入，只提示/跳转一次）
   - 有 refresh → 单飞刷新：`POST /api/Auth/refresh`，成功则 `setToken` 并重放队列中的请求
   - 刷新失败（抛错或 `status === false`）→ 同上提示并登出跳转，同时 reject 排队请求
3. 登出：清 Token/权限，并 `clearDynamicRoutes()`；布局侧通常再清空 `menuStore`

后端 Refresh 为**轮换制**（旧 refresh 立即失效），前端必须同时保存返回的新 `refreshToken`。

### 3.4 业务失败 vs HTTP 失败

响应拦截器对 JSON 体：`status === false` 且有 `message` → `ElMessage.error`。  
白名单（不 Toast）：`/api/Auth/login`、`/api/Auth/refresh`、`/api/Captcha/create`。

非 401 的 HTTP 错误默认只 `reject`，由调用方处理。

## 4. 路由与布局

### 4.1 静态 vs 动态

**静态**（`router/index.ts`）：

| 路径 | 说明 |
|------|------|
| `/login` | `meta.public`，免登录 |
| `/` → MainLayout | 子路由 `/home`、`/403` |

**动态**：登录后 `getMenu` → `buildMenuTree` → `featureStore.filterMenus` → `generateRoutes` → `router.addRoute('Layout', …)`。

组件解析（`import.meta.glob('../views/**/*.vue')`）优先级：

1. `views/{url路径}.vue`（如 `/Business/Device` → `views/Business/Device.vue`）
2. `views/system/{tableName}.vue`
3. 任意子目录同名 `.vue`（忽略大小写）

找不到组件时开发环境会 `console.warn`。

### 4.2 路由守卫（原理）

```
public? → 放行
未登录 → /login
permissionsSynced? → refreshPermissions()
routesLoaded? → 拉 Features + 菜单 → 注册动态路由 → next({ ...to, replace: true })
meta.permission 无权限 → Toast + /home（默认不跳 /403）
否则 next()
```

页面权限：`canAccessRoute` 要求具备 `{tableName}.Search`，或任意以 `{tableName}.` 开头的权限码。

`/403` 路由存在（`Forbidden.vue`），但守卫当前跳首页；可按产品需要改跳转。

### 4.3 KeepAlive 与标签页

- 动态页用 `namedRouteComponent(loader, routeName)` 包装，保证 `<script setup>` 组件有稳定 `name`
- `MainLayout`：`<keep-alive :include="tabsStore.keepAliveIncludes">`
- 打开菜单时 `tabsStore.addTab`；关闭标签与 `router.push` 联动
- **注意**：没有对 `route` 的全局 watch 自动加 tab，直接改 URL 可能不出现在标签栏

面包屑为「首页 + 当前标题」两级，非完整多级路径。

### 4.4 菜单同步

- API：`GET /api/Sys_Menu/getMenu`
- Store：`useMenuStore`（`stores/index.ts`）
- 侧栏文案：`useMenuLabel`（i18n key `menu.{中文名}`）
- 登出需 `routesLoaded = false` 并清空菜单，下次登录才会重新注册路由

## 5. Pinia Stores

| Store | 路径 | 用途 | 持久化 |
|-------|------|------|--------|
| `user` | `stores/user.ts` | Token、用户、权限 | 登录态字段；不含 permissions |
| `menu` | `stores/index.ts` | 菜单树、`routesLoaded` | 否 |
| `dict` | `stores/index.ts` | 字典缓存（按 dicNo 懒加载） | 否 |
| `tabs` | `stores/index.ts` | 多标签、`keepAliveIncludes` | 否 |
| `features` | `stores/features.ts` | 后端 FeatureFlags、菜单过滤 | 否（启动 load） |
| `theme` | `stores/theme.ts` | light / dark / system | 是 |
| `locale` | `stores/locale.ts` | vue-i18n + Element 语言 | 是 |
| `alarm` | `stores/alarm.ts` | 未读数、最近告警、Hub 状态 | 否 |

**未实现**：独立「系统配置」Store；标签页/字典持久化。配置类能力分散在 `features` + `.env`。

### 字典用法

```typescript
const dictStore = useDictStore()
await dictStore.loadDictionaries(['enable', 'gender'])
const options = dictStore.getOptions('enable')
```

内部走 `POST /api/Sys_Dictionary/getVueDictionary`。

## 6. Axios 封装

文件：`src/api/http.ts`。

| 能力 | 说明 |
|------|------|
| 实例 | `baseURL = VITE_API_BASE_URL`，`timeout: 30000` |
| 成功体 | `ApiResponse { status, message, data, code }`；拦截器直接返回 `data` 体（不是 AxiosResponse） |
| 请求 | 附加 Bearer |
| 401 | Refresh 队列（见 §3.3） |
| 业务失败 | `status:false` Toast（白名单除外） |
| 列表 | `getPageData('/api/{Table}/getPageData', options)` |
| 上传 | `uploadFile(url, file, fieldName)` → `FormData` |
| 下载 | `downloadFile` / `downloadGet`：独立 axios 调 blob，绕过 JSON 拦截器 |

CrudPanel 的导入导出、模板下载均走上述下载/上传封装。

## 7. 权限（前端）

后端权威在 JWT + `[Permission]`；前端负责**隐藏无权限 UI**与**拦截无权限路由**。完整配置步骤见 [04-权限与菜单](./04-权限与菜单.md)。

### 7.1 权限码格式

`{TableName}.{Action}`，如 `Sys_User.Add`、`Device.Export`。与菜单 Auth、角色 `AuthValue`、后端特性一致。

### 7.2 按钮权限

```vue
<!-- 指令：无权限 display:none !important，并监听 permissions 变化 -->
<el-button v-permission="'Sys_User.Add'">新增</el-button>

<!-- 数组：任一命中即可 -->
<el-button v-permission="['Device.Update', 'Device.Audit']">操作</el-button>
```

生成页 / 需要响应式更新时推荐：

```vue
<el-button v-if="userStore.hasPermission('Device.Add')">新增</el-button>
```

`hasPermission` **忽略大小写**精确匹配。实现：`directives/permission.ts`、`stores/user.ts`。

CrudPanel 内置按钮自动拼 `${tableName}.Add|Update|Delete|Import|Export`；扩展按钮用 `permission?: string` 过滤。

### 7.3 页面权限

动态路由 `meta.permission = menu.tableName`，守卫用 §4.2 的 `canAccessRoute`。

### 7.4 与架构文档的差异

无前端 Policy 引擎；无单独的「接口权限」客户端封装（一律带 JWT，由后端拒绝）。菜单项是否出现由后端 `getMenu` + Features 过滤决定。

### 9.1 主题

- `theme` Store：`light | dark | system`
- `utils/applyTheme.ts`：切换 `html.dark`、`data-seven-theme`、`color-scheme`
- 样式变量：`styles/theme.css`；Element 深色：`dark/css-vars.css`

无主题编辑器或多套品牌主题包；自定义主要靠改 CSS 变量。

详见 [08-国际化指南](./08-国际化指南.md)。

## 12. 新页面开发清单

手写系统页：

1. 在 `views/system/`（或业务目录）新增 `.vue`
2. 后端菜单：Url、TableName、Auth
3. 角色授权对应动作
4. 按钮用 `v-permission` / `hasPermission`
5. 列表调用 `getPageData('/api/Xxx/getPageData', …)`

生成业务页：

1. Builder 生成或照抄 `Device.vue` + `extension/Business/Xxx.ts`
2. 菜单 Url 指向正确路径（如 `/Business/Xxx`）
3. 扩展自定义逻辑，避免改会被覆盖的壳文件
