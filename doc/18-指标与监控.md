# 指标与监控（Prometheus / Grafana）

Seven 用 **Prometheus** 采集时间序列，用 **Grafana** 看图。与 [17-健康检查看板](./17-健康检查看板.md) 分工：

| | HealthChecks (`/health`、`/health-ui`) | 本栈 (`/metrics` + Grafana) |
|--|--|--|
| 用途 | 依赖是否健康（阈值） | CPU / 内存 / IO / HTTP 趋势 |
| 形态 | 绿黄红状态 | 曲线与速率 |

实现：`prometheus-net.AspNetCore`（`MetricsExtensions`）、`deploy/monitoring/`、`docker-compose.yml`。

---

## 1. Docker 中安装与启动 Prometheus + Grafana

本仓库已把监控栈写进 `docker-compose.yml`，**不必单独 `docker pull` 后再手写 run**；在装好 Docker 的机器上拉起 Compose 即完成「安装」。

### 1.1 前置条件

- 已安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows/macOS）或 Docker Engine + Compose 插件（Linux）。
- 终端能执行：`docker compose version`。
- 工作目录为仓库根：`Seven.Master`（与 `docker-compose.yml` 同级）。

### 1.2 会拉起哪些服务

| Compose 服务 | 镜像（版本见 compose） | 宿主机端口 | 作用 |
|--------------|------------------------|------------|------|
| `prometheus` | `prom/prometheus` | **9090** | 拉取并存储指标 |
| `grafana` | `grafana/grafana` | **3000** | 看图；账号见下 |
| `cadvisor` | `gcr.io/cadvisor/cadvisor` | **8081** | 容器 CPU/内存/磁盘 IO |
| `node-exporter` | `prom/node-exporter` | **9100** | 主机资源（Linux/WSL2 更完整） |
| `seven-api`（全量 up 时） | 本地 build | **5000** | 提供 `/metrics` 供 scrape |

Grafana 默认账号：**`admin` / `admin`**（环境变量 `GF_SECURITY_ADMIN_*`）。

### 1.3 配置文件位置（无需手装）

| 路径 | 说明 |
|------|------|
| `docker-compose.yml` | 定义上述服务、端口、卷挂载 |
| `deploy/monitoring/prometheus.yml` | scrape 目标：`seven-api:8080`、`cadvisor`、`node-exporter` |
| `deploy/monitoring/grafana/provisioning/datasources/datasource.yml` | 自动注册 Prometheus 数据源（`http://prometheus:9090`） |
| `deploy/monitoring/grafana/provisioning/dashboards/dashboards.yml` | 看板目录挂载 |
| `deploy/monitoring/grafana/dashboards/seven-overview.json` | 预置看板 **Seven Overview** |

首次启动时 Docker 会按 compose 中的 `image:` **自动下载**镜像；`gcr.io` 上的 cAdvisor 若很慢，可换国内镜像加速或改 compose 中的等价镜像，**保持端口映射 `8081:8080` 不变**。

### 1.4 一键启动（含 API + 监控）

```bash
cd Seven.Master
docker compose up -d
```

首次会 build `seven-api` 并拉镜像，耗时取决于网络。查看状态：

```bash
docker compose ps
docker compose logs -f prometheus grafana
```

### 1.5 验证是否安装成功

| 检查 | 操作 | 期望 |
|------|------|------|
| Prometheus UI | http://localhost:9090 | 能打开 |
| Targets | http://localhost:9090/targets | `seven-api`、`cadvisor`、`node-exporter` 为 **UP** |
| Grafana | http://localhost:3000 | `admin`/`admin` 登录 |
| 预置看板 | Dashboards → 文件夹 **Seven** → **Seven Overview** | 约 15s 后有曲线 |
| API 指标原文 | http://localhost:5000/metrics | 含 `process_` / `http_` 等 |
| cAdvisor（可选） | http://localhost:8081 | 容器列表页 |

预置看板含：API 请求速率、进程内存、容器 CPU/内存/磁盘 IO、主机 CPU%。

### 1.6 只安装/启动监控（不启 seven-api 容器）

本机用 VS / `dotnet run` 调试 API 时：

```powershell
cd Seven.Master
docker compose up -d prometheus grafana cadvisor node-exporter
```

此时 Prometheus 默认仍 scrape `seven-api:8080`（容器名），会失败。请改 `deploy/monitoring/prometheus.yml` 中 `seven-api` 目标为：

```yaml
  - job_name: seven-api
    metrics_path: /metrics
    static_configs:
      - targets: ["host.docker.internal:5000"]  # 本机 API 端口
```

然后重载配置：

```powershell
docker compose up -d prometheus
# 或
docker compose restart prometheus
```

更细说明见 **§2**。

### 1.7 修改配置后如何生效

- 改 **`prometheus.yml`**：保存后执行 `docker compose restart prometheus`（或 `up -d prometheus`）。
- 改 **Grafana provisioning / dashboard JSON**：一般需 `docker compose restart grafana`；预置文件以只读卷挂载，改仓库文件后重启即可。
- 改 **compose 中的镜像版本 / 端口**：改 `docker-compose.yml` 后执行 `docker compose up -d`。

### 1.8 常用运维命令

```bash
# 停止监控相关（保留其它服务）
docker compose stop prometheus grafana cadvisor node-exporter

# 停止并删除容器（数据：本配置未挂 Prometheus/Grafana 持久卷，历史会丢）
docker compose rm -f prometheus grafana cadvisor node-exporter

# 拉取更新镜像后再起
docker compose pull prometheus grafana
docker compose up -d prometheus grafana
```

### 1.9 常见问题

| 现象 | 处理 |
|------|------|
| `docker` 命令不存在 | 安装并启动 Docker Desktop，新开终端再试 |
| cAdvisor 拉取失败 / 超时 | 配置镜像加速，或临时注释 compose 中 `cadvisor` 与 prometheus.yml 里对应 job |
| `seven-api` Target DOWN | 确认 API 容器已起，或本机调试时改用 `host.docker.internal:端口`（§2） |
| Grafana 无数据源 / 无看板 | 检查 `deploy/monitoring/grafana/provisioning` 是否挂载成功：`docker compose logs grafana` |
| 端口被占用 | 修改 compose 中 `"3000:3000"` / `"9090:9090"` 左侧宿主机端口 |

## 2. 本机 `dotnet run` + Docker 监控

Compose 默认 scrape 的是容器内 `seven-api:8080`。若 API 用本机调试（如 `http://localhost:5000`）：

1. 只起监控：`docker compose up -d prometheus grafana cadvisor node-exporter`（见 §1.6）。
2. 将 `deploy/monitoring/prometheus.yml` 中 `seven-api` 的 `targets` 改为 `["host.docker.internal:5000"]`（端口与 `launchSettings.json` 一致）。
3. `docker compose up -d prometheus`。
4. 打开 http://localhost:3000 看 **Seven Overview**；http://localhost:9090/targets 中 `seven-api` 应为 UP。

全量容器部署（API 也在 Compose 内）时，请把 scrape 目标改回 `seven-api:8080`（仓库默认值）。

## 3. Prometheus + Grafana 安装（Windows，无 Docker）

适用于 IIS、双击 `Seven.WebApi.exe`、或本机不想用 Docker 的场景。先确认 API 已启动且 `http://<主机>:<端口>/metrics` 能打开。

官方下载页（版本以页面最新为准）：

- Prometheus：https://prometheus.io/download/（选 `windows-amd64.zip`）
- Grafana OSS：https://grafana.com/grafana/download?edition=oss&platform=windows（`.msi` 安装包或 zip）

### 3.1 安装并启动 Prometheus

1. 解压 zip，得到目录（示例）`C:\tools\prometheus\`，内含 `prometheus.exe`、`prometheus.yml`。
2. 编辑同目录下 `prometheus.yml`（或复制仓库 `deploy/monitoring/prometheus.yml` 后改目标）。最小可用示例：

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: seven-api
    metrics_path: /metrics
    static_configs:
      - targets: ["127.0.0.1:5000"]   # 改成 IIS / Kestrel 实际主机:端口
```

若还需采集本机 Windows 资源，先安装 [windows_exporter](https://github.com/prometheus-community/windows_exporter)（默认端口多为 `9182`），再追加：

```yaml
  - job_name: windows
    static_configs:
      - targets: ["127.0.0.1:9182"]
```

3. 在该目录打开 PowerShell / CMD：

```powershell
cd C:\tools\prometheus
.\prometheus.exe --config.file=prometheus.yml
```

4. 浏览器打开 http://localhost:9090 → **Status → Targets**：`seven-api` 应为 **UP**。  
   Graph 中可试查询：`process_working_set_bytes`。

常驻运行可选用 NSSM、Windows 服务，或任务计划程序；防火墙需放行 **9090**（若远程访问 Grafana）。

### 3.2 安装并启动 Grafana

**方式 A：MSI（推荐）**

1. 运行官方 Windows Installer（`.msi`），按向导安装。
2. 安装后服务一般会自动启动；默认地址 http://localhost:3000 。
3. 首次登录：用户名 `admin`，密码 `admin`（会提示修改）。

**方式 B：解压包**

1. 解压 standalone zip/tar.gz 到例如 `C:\tools\grafana\`。
2. 进入 `bin` 目录执行 `grafana-server.exe`（或文档中的启动脚本）。
3. 同样访问 http://localhost:3000 ，`admin` / `admin`。

### 3.3 配置数据源

1. Grafana → **Connections**（或 Configuration）→ **Data sources** → **Add data source**。
2. 选择 **Prometheus**。
3. URL 填：`http://127.0.0.1:9090`（Grafana 与 Prometheus 同机时）。
4. **Save & test**，应显示成功。

### 3.4 导入看板

1. **Dashboards** → **New** → **Import**。
2. 上传仓库文件：`deploy/monitoring/grafana/dashboards/seven-overview.json`，或粘贴其内容。
3. 选择刚建的 Prometheus 数据源 → Import。
4. 打开 **Seven Overview**：重点看 **API HTTP request rate**、**API process memory**。  
   标注 Container / Host（cAdvisor、node-exporter）的面板在无 Docker 时通常无数据，可忽略或删除。

也可在 Explore 中手写 PromQL，例如：

```promql
sum(rate(http_request_duration_seconds_count[1m]))
process_working_set_bytes{job="seven-api"}
```

（指标名以实际 `/metrics` 正文为准；若名称不同，在 Prometheus Graph 里用自动补全。）

### 3.5 端口与防火墙一览

| 组件 | 默认端口 | 说明 |
|------|----------|------|
| Seven API `/metrics` | 站点端口（如 5000 / IIS 绑定） | 必须先可访问 |
| Prometheus | 9090 | 采集与查询 |
| Grafana | 3000 | 看图 |
| windows_exporter（可选） | 9182 | Windows 主机指标 |

## 4. 无 Docker：IIS / 双击启动（场景说明）

### 4.1 始终可用（无需安装 Prometheus）

| 地址 | 说明 |
|------|------|
| `http://<主机>:<端口>/metrics` | 进程内存、HTTP 等 Prometheus 文本 |
| `http://<主机>:<端口>/health-ui` | 依赖健康看板 |
| `http://<主机>:<端口>/health` | 探针 JSON |

确认防火墙已放行对应端口。

### 4.2 要曲线图时

按 **§3** 在 Windows 上安装 Prometheus + Grafana，scrape 指向 IIS / 本机 API 地址。

### 4.3 主机 CPU / 磁盘

- Compose 的 **cAdvisor**、**node-exporter** 面向 Linux 容器/主机，不适合纯 IIS / WinServer。
- 使用 [windows_exporter](https://github.com/prometheus-community/windows_exporter)，配置见 §3.1。

### 4.4 对照

| 能力 | Docker Compose | IIS / 双击启动 |
|------|----------------|----------------|
| `/metrics`、`/health-ui` | 有 | 有 |
| Grafana 曲线 | Compose 一键 | 按 §3 自行安装 |
| 容器 CPU/IO | cAdvisor | 不适用 |
| 主机资源 | node-exporter | windows_exporter（可选） |

---

## 5. 安全与平台说明

- 本栈面向**本地 / 内网**。勿把 `/metrics`、Grafana、cAdvisor、Prometheus 裸暴露公网。
- **Windows Docker Desktop** 上 cAdvisor / node-exporter 指标可能不全；完整主机/容器 IO 建议 Linux 或 WSL2 后端。
- cAdvisor 镜像来自 `gcr.io`，拉取较慢时可换镜像加速或等价镜像，保持端口 `8081:8080`。
